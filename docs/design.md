# Project Aero 设计定稿

> 2026-08 定稿。所有规则修改均经用户逐条确认，实施时以此为准。

## 1. 规则定稿

1. **棋盘与飞机**：10×10 / 15×15 / 20×20（自定义 height×width ∈ [10,26]，横坐标字母、纵坐标数字）。默认飞机 4 行×5 列共 10 格：机头 1、机翼 5、机身 1、机尾 3，左右对称，四向旋转均合法。自定义飞机：5×5 内绘制，四邻连通、2~15 格、恰 1 机头。
2. **报点与反馈**：报点"字母+数字"，大小写/空白容错。无飞机→"击空"；非机头部件→"击中"；机头→"击毁"。**被击毁飞机的其余格位一律不公开**，之后对残骸任意格报点按"无效打击"返回"击空"（残骸与空格在对手视野中不可区分，误导对手是核心策略）。已报点格 UI 禁点、协议拒绝重复报点（无效打击仅作异常输入兜底）。
3. **胜负**：轮流报点，一方全部飞机被击毁则对方胜；终局公开双方真实阵型。
4. **绝地反击**：仅当先手方一次行动击毁对方全部飞机、且自身恰剩 1 架时触发；后手获恰好一次额外报点，仅命中机头判后手胜，其余情形（命中非机头/击空/命中先手残骸）判先手胜；后手自己全歼不触发；先手剩 ≥2 架直接判先手胜。

## 3. 单机流程

0. 双方 id（我方 + 电脑）→ 1. 摆阵（拖拽吸附、点击旋转 90°、重叠红遮罩、清空/随机摆阵、校验清单）→ 2. 等概率随机先后手（横幅 1.5s）→ 3. 对战界面（我方网格 1/2 缩小置竖版右上/横版右侧，对手网格居中，样式参考图 5×5 置竖版左上/横版左侧，顶部状态条+倒计时（单机隐藏），底部坐标输入框）→ 4. 报点：鼠标点两次报点 / 输入框+回车 → 5. 标记：击空=黑叉✗、击中=深绿空心圈◯、击毁=深红五角星★（盖章质感），击毁仅标机头格，我方被毁飞机暗色标出（仅本人可见）；对方报点在我方网格 0.8s 高亮动画+状态条文字 → 6. 结算：胜负文案+双方真实阵型+统计（回合数/命中率/击毁架数）+"再来一局"/"返回主页"；任意阶段退出二次确认。

## 4. 设置

BGM/音效两推杆（可试听）、"反转 X 与 O"开关（✗/◯ 含义对调，本地显示偏好，两网格同生效，不影响裁决）、AI 难度选单（简单/正常/困难/地狱，仅单机）。localStorage 持久化。

## 5. 联机方案

- **架构**：单一 WebSocket 后端 + 房间制 + 服务端权威（双方阵型仅存服务端，客户端只发报点、只收裁决）。
- **三入口**：局域网对局（6 位房码+二维码/链接）；公网匹配（按标准三档同配置配对，自定义不进匹配池，30s 未配提示自建）；自定义房间（房主配置棋盘+形状——形状双方一致——+时限）。
- **协议事件**：C→S `auth/createRoom/joinRoom/leaveRoom/placeFleet/ready/shoot/resign/reconnect`；S→C `identity/roomUpdate/phaseChange/turnStart/shotResult/timerUpdate/machineTakeover/opponentDisconnected/opponentReconnected/matchmakingStatus/gameEnd`。
- **状态机**：waiting → placing（双方就绪）→ playing（回合制）→ ended。
- **计时（围棋读秒制）**：每回合默认 30s；超时消耗 1 次全局机会（共 3 次），并由系统为该方代走一步（随机报点）；机会耗尽后每回合降档 10s；此后首次超时 = 机器永久接管该席位（"正常"级 AI 代打，广播接管事件）。自定义房间可选每步 10/20/30/60 秒/不限（不限时不倒计时、不超时、不接管）；waiting/placing 残留房间在再次建房/入房/匹配时自动释放。
- **断线重连**：60s 内凭 token+gameId 恢复；超时/投降/退出判负；摆阵阶段断线 60s 房间解散。

## 6. 身份与数据

游客身份："游客XXXXX"（5 位数字），token 存 localStorage，服务端 users 表持久化，重名冲突重新生成。SQLite：users / games（阵型、全量报点、结果、时长）/ stats。

## 7. AI 设计

统一框架：概率热图 + 猎杀/围杀 + 参数化缺陷。基础能力（各级共有）：永不重复/越界报点、反馈状态机。
- **简单**：hunt 纯随机（含 10% "遗忘"）；摆阵随机。
- **正常**：随机 hunt；命中后围杀 4 邻格；摆阵随机合法。
- **困难**（v0.2.7 起）：全局覆盖热图 + 残骸多解建模 + 习惯先验 + ≤5% 扰动；摆阵=簇式"局部密铺+整体分散"。
- **地狱**（v0.2.7 起）：机头概率热图（head-hunting）——每枪射向当前局部最可能的机头位置，直接击杀最大化、无效报点显著减少；摆阵同困难的簇式算法（密铺更强）。

约束：AI 只消费自身报点历史与反馈，绝不读玩家阵型；26×26 毫秒级；行动延迟 300~900ms；AI 摆阵模块复用于玩家"随机摆阵"与联机"机器接管"。

## 8. 视觉（纸感）

纸张质感=CSS 多层背景（feTurbulence 噪点+脏污渐变+纤维纹理）；纸卡按钮（微阴影+按压下沉）；SVG 贝塞尔曲线飞机（严格占满格子，机头=深色圆形座舱，机身淡色+墨线）；盖章墨迹标记；霞鹜文楷 LXGW WenKai（OFL）；铅笔/盖章/纸张音效（CC0 或程序合成）；响应式=matchMedia+resize 按可用宽高比切横/竖版。
